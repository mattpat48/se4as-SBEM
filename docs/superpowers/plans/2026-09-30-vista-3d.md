# Vista 3D (fase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `view` service — a browser 3D/2D view of the residential complex (4 buildings, park, parking) that renders live data from the simulator over MQTT/WebSocket, with a debug panel for actuator commands and the simulated clock.

**Architecture:** A static React + React Three Fiber app served by nginx. The browser connects directly to Mosquitto on a new WebSocket listener (port 9001) as a least-privilege user `view` (ACL). Strict one-way layering: `mqtt/` → `store/` → `scene/` + `ui/`, all using pure, unit-tested functions in `domain/` (no React, no Three.js there). Live readings bypass React re-renders: the scene reads the stores inside `useFrame`.

**Tech Stack:** TypeScript, React 19, three.js, @react-three/fiber 9, @react-three/drei 10, zustand 5, mqtt.js 5, Vite, vitest; nginx:alpine; Mosquitto 2 (WebSocket + ACL); Python 3.11 + paho-mqtt for the end-to-end script.

**Spec:** `docs/superpowers/specs/2026-09-30-vista-3d-design.md` (every section number below, "§x", refers to it). Status tracker: `docs/VISTA_3D.md`. Data contract: `docs/superpowers/specs/2026-09-30-monitor-v2-design.md` §5–§7.

## Global Constraints

- **Prerequisite:** the simulator work on `feature/monitor-v2-simulator` is committed by the user; then work on a new branch `feature/vista-3d` created from it. **Do not run `git commit`**: the user commits. Each task ends with a *Checkpoint* step listing the files it touched.
- Everything new lives in `view/`, except the files listed in §14 (Mosquitto config, `.env`, `docker-compose.yml`, `config/complex.json`, `scripts/e2e_view.py`, docs).
- Commands run from `view/`: tests `npm test -- <file>` (vitest run), types `npm run check` (`tsc --noEmit`), dev server `npm run dev` (Vite, port 5173). The Docker build runs `npm run check && npm test && npm run build` and fails if any fails.
- `domain/` imports neither React nor three.js nor mqtt.js. `scene/` never imports `mqtt/`. `ui/` talks to MQTT only through `store/commands.ts` and `store/connection.ts` actions.
- Libraries: only those in the Tech Stack line plus `@vitejs/plugin-react`, `@types/react`, `@types/react-dom`, `@types/three`. Keep the majors listed (R3F 9 requires React 19).
- Topic root `Complex`; device topics `Complex/<layer>/<area>/<unit_id>/<device_type>`; device id `<unit_id>.<type>` (Monitor v2 spec §4, §7).
- `Complex/status/<service>` payloads are **plain text** (`online`/`offline`), not JSON. All other payloads are JSON.
- `sim_time` is naive local time of L'Aquila (`Europe/Rome`), ISO without zone. The view represents it as "naive ms" = `Date.UTC(y, m-1, d, h, mi, s)`.
- Debug commands always carry `"issued_by": "debug"`. The view never publishes on `Complex/control/scenario`.
- MQTT user `view`, password `viewpassword123` (same convention as `admin`/`adminpassword123`); env `VIEW_MQTT_URL=ws://localhost:9001`, `VIEW_MQTT_USERNAME=view`, `VIEW_MQTT_PASSWORD=viewpassword123`.
- Never start Node-RED while testing (it forwards alarms to a real Telegram channel). Stack for tests: `docker compose up -d --build mosquitto simulator view`.
- Identifiers and code comments in English (like the existing code); UI copy and documentation in Italian, with the exact strings given in this plan.
- Numeric values (distances, thresholds, scales, timings) are copied from the spec; when a task pins a number, use exactly that number.

## Review Focus

1. **Plain-text status payloads**: `Complex/status/simulator` carries `online`/`offline` as bare text. Treating it as JSON would drop it, and the "simulatore non in linea" banner would never appear → Task 3 `parseStatus accepts plain text`, Task 5 `status offline then online`.
2. **Simulator restart with the page open**: the retained `Complex/model` is re-sent. If it is identical, the live data must be kept; if it differs, the scene must be rebuilt and live data cleared. The Last Will `offline` followed by `online` must clear the banner → Task 5 `same model twice keeps readings`, `different model clears live data`.
3. **Wrong credentials or broker down**: mqtt.js keeps retrying. The user must see "credenziali rifiutate" or "broker non raggiungibile, riprovo…" instead of an empty scene → Task 5 `auth error sets auth_failed`, `close sets offline`.
4. **Clock jumps** (`jump_to` a January date, or going backwards): the local advance must restart from the new `sim_time`, and the sun must stay finite for any date → Task 4 `earlier sim_time replaces state`, Task 13 `sun is finite on 2027-01-15`.
5. **Password with `"` or `\` in `VIEW_MQTT_PASSWORD`**: it would produce broken `config.js`. The entrypoint must refuse to start with a clear message → Task 2, Step 6 (behaviour) and Step 8 (check).
